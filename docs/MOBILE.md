# DegenFeed — Mobile Native App (Capacitor)

DegenFeed uses [Capacitor](https://capacitorjs.com) v8 to wrap the Next.js PWA into
native iOS and Android apps.  This gives us push notifications, native share sheets,
deep linking, and full App Store / Play Store distribution — all while sharing the
same codebase.

## Architecture

```
apps/web/
├── capacitor.config.ts        ← Capacitor configuration
├── src/lib/
│   ├── capacitorPush.ts       ← Push notification wrapper (native + Web Push)
│   └── capacitorShare.ts      ← Share sheet wrapper (native + Web Share)
├── public/
│   ├── manifest.json          ← PWA manifest (updated with native metadata)
│   └── .well-known/
│       ├── apple-app-site-association  ← iOS Universal Links
│       └── assetlinks.json            ← Android App Links
ios/                            ← Xcode project (generated by npx cap add ios)
android/                        ← Android Studio project (generated by npx cap add android)
```

### Key dependencies

| Package | Purpose |
|---------|---------|
| `@capacitor/core` | Core runtime |
| `@capacitor/cli` | CLI tool (`npx cap sync`, `npx cap open`) |
| `@capacitor/ios` | iOS platform hooks |
| `@capacitor/android` | Android platform hooks |
| `@capacitor/push-notifications` | Native push registration / handling |
| `@capacitor/share` | Native share sheet |
| `@capacitor/splash-screen` | Splash / launch screen |
| `@capacitor/status-bar` | Status bar styling |

## Getting Started

### Prerequisites

| Tool | Version | Notes |
|------|---------|-------|
| Node.js | 20+ | Required by Next.js |
| pnpm | 9+ | Package manager |
| Xcode | 16+ | **macOS only** — iOS builds require a Mac |
| CocoaPods | 1.15+ | `gem install cocoapods` |
| Android Studio | Latest | Required for Android builds |
| JDK | 17+ | Set `JAVA_HOME` |
| Android SDK | 34+ | Install via Android Studio SDK Manager |

### 1. Install dependencies

```bash
cd apps/web
pnpm install
```

### 2. Add native platforms

**⚠️ Requires Xcode (macOS) or Android Studio on the machine.**

```bash
cd apps/web
npx cap add ios
npx cap add android
```

These commands create the `ios/` and `android/` directories with native project
files.  They are **not checked in** — each developer runs `npx cap add` locally
or CI generates them.

### 3. Configure placeholders

Before building, update the **team ID** and **certificate fingerprints** in the
deep-linking config files:

- `public/.well-known/apple-app-site-association` — replace `TEAMID` with your
  Apple Developer Team ID.
- `public/.well-known/assetlinks.json` — replace
  `CHANGE_ME:YOUR_APP_SIGNING_CERTIFICATE_SHA256` with your Android signing
  certificate SHA-256 fingerprint.

## iOS Build

### Quick start (dev)

```bash
./scripts/build-ios.sh
```

This runs:
1. `next build` — builds the Next.js app (standalone output).
2. `npx cap sync ios` — copies web assets into the iOS project.
3. `pod install` — installs CocoaPods dependencies.
4. Opens Xcode — hit **Run** (⌘R) to launch on simulator or connected device.

### Production archive

```bash
./scripts/build-ios.sh --release --no-open
```

Then:

```bash
open build/DegenFeed.xcarchive
```

Use the **Organizer** window in Xcode to **Distribute App** → App Store Connect.

### Manual steps (if script fails)

```bash
cd apps/web
pnpm build
npx cap sync ios
cd ios
pod install --silent
open App/App.xcworkspace
```

### Required Xcode settings

| Setting | Value |
|---------|-------|
| Team | Your Apple Developer team |
| Bundle Identifier | `xyz.degenfeed.app` |
| Deployment Target | iOS 17.0+ |
| Signing | Automatic (or manual with distribution cert) |
| Capabilities | Push Notifications, Associated Domains |

## Android Build

### Quick start (dev)

```bash
./scripts/build-android.sh
```

This runs:
1. `next build` — builds the Next.js app.
2. `npx cap sync android` — copies web assets into the Android project.
3. Opens Android Studio — hit **Run** (▶) on emulator or device.

### Production APK & AAB

```bash
./scripts/build-android.sh --release --no-open
```

Outputs:

- APK: `android/app/build/outputs/apk/release/app-release.apk`
- AAB: `android/app/build/outputs/bundle/release/app-release.aab`

Upload the AAB to Google Play Console.

### Manual steps (if script fails)

```bash
cd apps/web
pnpm build
npx cap sync android
cd android
./gradlew assembleRelease   # for APK
./gradlew bundleRelease     # for AAB
```

### Required Android Studio settings

| Setting | Value |
|---------|-------|
| Application ID | `xyz.degenfeed.app` |
| Min SDK | 29 (Android 10) |
| Target SDK | 34 |
| Signing | Release key (create in Build → Generate Signed Bundle/APK) |

## Push Notifications

### Architecture

```
┌──────────────┐    ┌──────────────────┐    ┌─────────────────┐
│ Capacitor     │───▶│ pushService      │───▶│ /api/push/      │
│ PushNotifications│  │ (client wrapper) │    │   register      │
└──────────────┘    └──────────────────┘    └────────┬────────┘
                                                     │
                                                     ▼
                                            ┌─────────────────┐
                                            │ Your push server │
                                            │ (APNs / FCM)     │
                                            └─────────────────┘
```

The `capacitorPush.ts` wrapper (`pushService`) handles:

- **Native (iOS/Android)**: Uses `@capacitor/push-notifications` to register with
  APNs / FCM and emits the token via `pushService.onToken()`.
- **Web / PWA**: Falls back to the Web Push API (requires a VAPID key) and
  registers via the existing service worker at `/sw.js`.

### APNs setup (iOS)

1. **Apple Developer Portal**:
   - Enable **Push Notifications** capability in Xcode (it adds the entitlement
     automatically).
   - Generate an **APNs authentication key** (`.p8` file) in Certificates,
     Identifiers & Profiles → Keys.
   - Note the **Key ID** and **Team ID**.

2. **Server side**:
   - Your push relay server needs the APNs key to send notifications to iOS
     devices.
   - Each iOS device receives an APNs device token via `PushNotifications.register()`.

### FCM setup (Android)

1. **Firebase Console**:
   - Create a Firebase project (or add Android app to existing project).
   - Register the app with package name `xyz.degenfeed.app`.
   - Download `google-services.json` and place it at:
     ```
     android/app/google-services.json
     ```

2. **Server side**:
   - Use the **Server key** from Firebase Cloud Messaging to send notifications
     to Android devices.

### Web Push (PWA fallback)

Set the VAPID public key in your environment:

```bash
# apps/web/.env.local
NEXT_PUBLIC_VAPID_KEY=YOUR_VAPID_PUBLIC_KEY
```

Generate a VAPID key pair:

```bash
npx web-push generate-vapid-keys
```

## Deep Linking

### iOS Universal Links

1. The `apple-app-site-association` file is served at:
   ```
   https://app.degenfeed.xyz/.well-known/apple-app-site-association
   ```
2. In Xcode, enable **Associated Domains** capability and add:
   ```
   applinks:app.degenfeed.xyz
   ```

### Android App Links

1. The `assetlinks.json` file is served at:
   ```
   https://app.degenfeed.xyz/.well-known/assetlinks.json
   ```
2. Update the SHA-256 fingerprint in `assetlinks.json` with your release
   certificate fingerprint.
3. Verify with the [App Links Assistant](https://developer.android.com/training/app-links/verify-android-applinks)
   in Android Studio.

### Custom URL scheme

The app also supports a custom URL scheme: `degenfeed://`

Configured in `capacitor.config.ts`:

```typescript
deepLinking: {
  customScheme: 'degenfeed',
  domains: ['app.degenfeed.xyz'],
}
```

This allows links like `degenfeed://post/0x123` to open the app directly.

## App Store Submission

### Checklist

- [ ] App Store Connect record created with bundle ID `xyz.degenfeed.app`
- [ ] App icons: 1024×1024 PNG (no transparency)
- [ ] Screenshots for all required devices (6.7", 6.5", 5.5" + iPad if applicable)

Increment `CFBundleVersion` in `ios/App/App.xcodeproj/project.pbxproj` or use
`npx cap open ios` and update the Xcode target.

## CI / CD

The existing GitHub Actions pipelines should be extended with:

```yaml
# .github/workflows/mobile-ios.yml
- run: npx cap sync ios
- run: xcodebuild -workspace ios/App/App.xcworkspace -scheme App -sdk iphoneos archive

# .github/workflows/mobile-android.yml
- run: npx cap sync android
- run: cd android && ./gradlew assembleRelease
```

> **Note:** iOS builds require a macOS runner.  Both pipelines need signing
> certificates (match / fastlane recommended).

## Troubleshooting

### `npx cap sync` hangs or fails

```bash
cd apps/web
rm -rf node_modules/.cache
pnpm build
npx cap sync
```

### CocoaPods fails on Apple Silicon

```bash
sudo arch -x86_64 gem install ffi
arch -x86_64 pod install
```

### Push token not received (iOS)

1. Ensure **Push Notifications** capability is enabled in Xcode.
2. Test on a **real device** — push does not work on the simulator.
3. Check that the provisioning profile includes push.

### Push token not received (Android)

1. Verify `google-services.json` is present and correct.
2. Ensure FCM is enabled in Firebase Console.
3. Check `android/app/build.gradle` has `implementation platform('com.google.firebase:firebase-bom')`.

### App links not opening

1. Verify the AASA / assetlinks files are accessible via HTTPS (not HTTP) with
   content-type `application/json` (AASA) or `application/json` (assetlinks).
2. Use Apple's [validation tool](https://search.developer.apple.com/appsearch-validation-tool/).
3. For Android, use the App Links Assistant in Android Studio.
